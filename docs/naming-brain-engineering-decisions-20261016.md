# Naming brain: local engineering decisions, 2026-10-16

These are engineering choices made while implementing the user-approved Naming
plan. They are distinct from the product decisions and authority recorded in
[D069](decisions.md). The implementation is still undergoing local review and
integration; this document is not evidence of live activation or provider access.
See the [design](superpowers/specs/2026-10-16-naming-brain-design.md) and
[implementation plan](superpowers/plans/2026-10-16-naming-brain.md).

| Choice | Reason | Cost if the choice is wrong |
| --- | --- | --- |
| Separate output completion from accounting. Hold the full US$5 admitted allowance until verified reconciliation, within the US$25 aggregate ceiling and at most five fully held unreconciled runs. | The available managed usage observations do not establish the final charge. Estimates, native counters and caps cannot become confirmed expense or refunds. | The pilot may pause early or require accounting changes. No additional allowance is implied. |
| Use a fresh capped session per Creator assignment, with native delegation disabled and at most three concurrent Creators. | Application scheduling provides explicit call limits, independent sibling outputs and real root-turn/final-item provenance. | Session setup may increase latency. The five roles, 150 initial candidate target and 150-cent creation envelope remain fixed. |
| Give Research and Verification a narrow root-only reference reader, using directly pinned parse5 8.0.1. | Search URL metadata does not supply the retained page text and quote evidence needed here. The reader permits only reviewed public HTTPS host/path combinations, with no redirects, credentials or executable parsing. | Some sources remain unavailable, or extraction needs more work. Missing evidence cannot become a verified fact. |
| Scope the complete new Naming lifecycle to V2 while retaining `jobs.policy_identity = NULL` for API jobs. | Existing Strategy/subscription and generic expiry helpers do not authorize this managed workflow. Run/input/batch retain its accepted policy identity. | Recovery or least-privilege permissions may need rework. Generic service-role or direct-table shortcuts remain prohibited. |
| Keep Curator and Verifier review in compact single-call projections with shared evidence once. | This preserves complete candidate/claim coverage under the 131072-byte wire limit without introducing unreviewed extra calls. Oversized requests stop before dispatch. | Verbose pools may remain incomplete until a future bounded review design is approved. No truncation or automatic extra calls are allowed. |
| Start UI work from the reviewed public contract subset while provider-only contract fixes finish. | Public widgets/feed/memory paths were disjoint from those pending fixes, allowing the approved local parallel work to progress. | Imports or tests may need reconciliation. This did not approve unfinished contracts or activate providers. |
| Persist a paused exploration head and sequence-fenced idempotent Stop, with a narrowly receipt-bound pending-ensure exception. | Canceling a job alone cannot fence late scroll demand or Stop before a lost admission acknowledgement. Explicit continuation may reuse eligible saved output; incomplete paid continuation gets a linked run. | Head-state and recovery APIs may need changes. No extra budget or automatic paid retry is allowed. |
| Freeze the gap's ordered envelopes before I/O: direction 10 cents, creation 40, curation 5, verification 20; search maxima 0/0/0/8. Freeze each exact request after its dependencies exist. | A later phase cannot be hashed before earlier model output defines its input. | Small phase caps may produce partial results or need a future versioned allocation. The 75-cent total, eight searches, one gap and no re-lending remain fixed. |
| Permit scoped `resume_execution` only when all issued current-stage calls have genuine completed artifacts and the original execution gates still pass. | Observation-only crash recovery otherwise cannot advance original unissued phases. Fresh paid authorization, original plans/caps/deadline, and no uncertainty, overrun, cancellation or pause are required. | Recovery may need rework. Issued calls must never be recreated or the operation expanded. |
| Require readiness attestations from the existing restricted Node worker, bound to immutable preference version/hash and exact implementation/runtime fingerprint. | The shared JavaScript Unicode normalization and the installed database case conversion demonstrably differ. SQL admission must use the actual shared readiness result. | Validation may add delay or require adapter work. No client readiness flag, custom case table, new service, credential or paid job is introduced; draft saves and free saved-output consumption remain independent. |
| Bound known-session observation recovery to 12 claims and one hour, with persisted backoff from 30 seconds to five minutes. | Evidence recovery must survive withdrawal of paid authorization without looping indefinitely. Original principal, session identity, cancellation and full liability remain intact. | A run may need manual resolution after the observation window. No replacement inference or assumed zero expense is allowed. |
| Allow a known terminal failed gap attempt to reach the actual registered prepare stage using the last fully reviewed pool and truthful partial fulfillment. | Failing the outer gap step would prevent valid retained names from being prepared. Genuine terminal evidence and valid saved artifacts distinguish this from unknown execution. | Terminal-evidence handling may need rework. No invented model success/artifact, inline prepare, unknown-outcome publication, refund or extra round is permitted. |
| Replace old V1 preference-form browser assertions with preservation and explicit V2-upgrade coverage. | The new widgets edit Naming choices. Saved V1 locale, notes and length bounds carry into an unsaved V2 draft; approaches/directness are not inferred. Legacy batches, history and Workshop remain accessible, and mount/navigation performs no upgrade write or admission. | Users needing the old editing flow may require an explicit legacy entrypoint. Tests must still catch lost values/history or an implicit billing/version switch. |

Local validation also corrected two implementation assumptions without changing
the shared contract: `normalizeNamingText` applies NFC both before and after
lowercasing, and this installed Zod version counts code points for string length
limits. Database predicates and worker attestations must follow those actual
semantics. Synthetic tests do not establish live provider behavior, native
Postgres login/pooler isolation, or final billing.
