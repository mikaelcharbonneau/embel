## Explicit evidence partition

The Director receives allocation version 2 and returns a distinct
`planVersion: 2` artifact. `assignments` contains usable supported directions;
`unavailableApproaches` records unsupported selected factual routes. Together
their primary approaches must partition every originally selected approach,
without overlap, omission, unselected approaches or unsupported secondary tags.
Creative directions can use the actual brief without inventing factual support.

Every supported factual direction requires keys for actual retrieved passages.
The Creator must still state explicit unverified primary claims tied to those
keys, and the independent Verifier must bind supporting quoted passages before
any factual primary credit can be published. A Director calling a route usable
does not establish the truth of an attribution.

Unavailable routes retain a concrete explanation and one of two bounded
structural reasons. `no_retrieved_evidence` requires that research contains no
retrieved passage, with no inspected keys. `retrieved_evidence_not_applicable`
requires actual inspected retrieved keys and an explanation of their limitation
for this route. A URL alone is insufficient, and an invented network failure
cannot substitute for an observed research limitation.

With any supported route, the output contains fifteen reusable directions of ten
raw targets. If every selected factual route is unavailable, it contains zero
directions and an unavailable record for each selected route. The ordinary JSON
schema bounds each candidate direction and allows the exact fifteen-or-zero
cases; semantic validation checks the complete partition and allocation.
