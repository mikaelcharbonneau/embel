# Naming lease expiry release — November 7, 2026

This release publishes source `df783c5de32bfd5db7666a7c6284a077716a049b`
([PR #194](https://github.com/mikaelcharbonneau/embel/pull/194), "Expire
interrupted Naming jobs on the shared worker pool") to the shared worker and
applies its one reviewed forward packet to the production database. The web app
is unchanged: PR #194 touches no `src/` code, and `/api/health` still reports
release `b0444144e193526acc122d5fa8380d7cd1329a85`.

Before this release, a shared Naming job whose worker stopped kept its expired
lease and stayed `running` indefinitely. The Naming lane now calls the new
slot-level `expire` action before every claim. See
[Naming lease expiry](naming-lease-expiry.md) for its rules.

## Rollback

With fresh drain witnesses, scale the daemon to 0 and apply
[`rollback_naming_lease_expiry.sql`](../supabase/operator/rollback_naming_lease_expiry.sql)
under the same stopped, locked owner procedure. It removes only the `expire`
branch and function, and confirms the gateway returns to
`1a044e660bde27bf2d16cb3acce55fbe3e4f6bb88ada104ef354cc9b39c58d4f`. Job states
already moved by expiry stay as they are. Restore the previous configuration
value (SHA-256 above), append a receipted rollover that returns the three slots
to `dpl_692WHueaHqwwFjjLRbMmfxDL4FJZ`, request a production rollback of the
worker project to that deployment, and scale back to 1. After readiness, append
Naming revision 14 for the old deployment; never delete revision 13. The web
needs no rollback.
