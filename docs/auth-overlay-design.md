# Sign-in overlay

Approved reference: [Fluid — Screens, Sign In](https://www.figma.com/design/HP219GuYbpE8F1wHxj0h6N/Fluid-Screens?node-id=3-14), page 3:14, frame 7:9224 (1440 × 900). The original 460 px card, Geist typography, inputs, buttons, 16 px grid and SVG artwork are retained. The generic account avatar reflects the existing verified identity contract.

Workspace links open the card in a native modal dialog with keyboard focus containment, Escape, backdrop and close-button dismissal. Next.js intercepted/parallel routes preserve the underlying workspace and browser history; direct visits and reloads show the standalone page. Closing or leaving clears the form DOM without aborting a pending cookie mutation or releasing its shared authentication guard. The existing same-origin API, immediate password clearing, generic errors, verified-session refresh, prompt recovery and private owner/generation fences remain authoritative.

The original reference contains existing-account email/password sign-in and explicitly unavailable account creation. D060 subsequently authorizes email/password signup using this same card, including confirmation and resend recovery; see [account creation](account-creation.md). Password reset, OAuth and account linking remain unavailable. Unconfigured authentication disables the fields and submission, and browser drafts remain available independently. Signing in does not automatically copy browser drafts to an account.

Verification uses a dedicated headless Chromium browser and synthetic same-origin account responses. Fixture sign-in does not establish live provider acceptance. Non-secret receipts and captures are stored outside the checkout under `/workspace/scratch/fluid-auth-overlay-figma-20261010/`. Publication follows the standing protected-preview milestone approval, retaining Vercel Authentication for all deployments.

For the original overlay checkpoint, typecheck, full lint, scoped final lint and the production build passed. Six focused suites passed 43 checks. Twenty-six distinct desktop/mobile browser scenarios passed across the overlay, existing authentication and Home recovery suites. Configured-auth cases use inert server configuration with every account API intercepted; they never authenticate against a live provider. The sixteen original SVG exports are byte-verified, including native 32 px card mark, 17 px submit arrow and 1360 × 900 grid. Desktop fallback geometry is x=530, y=176, width=460; unavailable-account status grows the card honestly. Mobile checks confirm no horizontal overflow and accessible dialog dismissal. Signup validation is recorded separately in account-creation.md.
