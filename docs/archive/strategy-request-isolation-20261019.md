## Implemented correction

The additive migration keeps the original global guard and helper behavior for
ordinary accounts and reads without a target project. The existing operator
testing authority can use an owned project's Strategy lane. Unresolved Strategy
requests across the account and uncertainty in that project remain blockers;
unrelated Naming work retains its original state and financial holds. Existing
Logo resolution witnesses are checked exactly and become invalid if their bound
evidence changes. Owner-wide actual and observed overruns remain blockers.

Availability and both admission checks use the same project scope. Worker claim,
descriptor, runtime and final step/dispatch gates derive that project from the
existing private gateway and immutable job; no caller flag confers authority.
The migration changes no stored row or grant and preserves original public
function signatures, OIDs and security metadata. Its eight predecessor bodies
and metadata match the actual hosted catalog.

The conversation and Settings accept `request_unresolved` and `request_active`.
Initial messages show the real reason, blocked requests do not offer a false
retry, and unavailable copy does not claim pending edits are saved. The normal
Thinking/Stop, saving, saved and recovery behavior remains in place.
