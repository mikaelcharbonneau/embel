# Brainstorm event capacity and saved-response recovery

> Historical: retired by the November 2026 Naming generation rebuild (docs/naming-generation-contract.md).

The 2026-10-29 first fast-first live request retained one response ID but could not persist its completed event. PostgreSQL reported SQLSTATE 54000: `index row requires 15648 bytes, maximum size is 8191`. The existing `UNIQUE(call_id,payload)` B-tree indexed the entire response JSON. A separate GET-only diagnostic established that the original response completed with 113 structured candidates and the exact requested model/metadata. This is evidence of a saved response, not evidence of published names or a known dollar cost.

The frozen `shared_naming_brainstorm.sql` packet and its applied ledger remain unchanged. The forward `shared_naming_brainstorm_event_capacity.sql` packet replaces only the oversized unique index with a nonunique `(call_id,jsonb_hash_extended(payload,0))` bucket index and an insert trigger. The trigger serializes writers on the exact parent call and compares full JSONB equality. Hash collisions retain distinct values, and numerically equal JSONB representations still deduplicate. Inserts require READ COMMITTED so the equality check after the parent lock sees concurrent commits. Other isolation levels fail closed; no global setting changes. Existing immutable events are not rewritten.

Real terminal replay also exposed an ambiguous `payload` column in the deployed gateway. The same forward packet qualifies exactly that column reference, preserving the gateway OID, ACL, owner and every other body byte. The old body hash `e8bae9ed6a46f0b87e8c78474d5d059dd608b27442421e730d2f0c9f4e599ea4` changes to `5b9e16f786364d7cb5e58a5b9380a1da3490f5c950f8dfb7f47fde435518d7f9`. The new private invoker trigger body is pinned as `e63cc7846deb8f7480fdf713943121ff7fcc9f0da7ca231e2ac8dfc945687d4c`. It receives no public, customer or service-role grant. The runtime authority manifest includes this exact additive packet and both corrected source pins.

Fresh shared installs append the unchanged Naming packet and then the forward correction after the two existing Storage post-install corrections. The historical ten packet bodies are unchanged. Non-shared installers are unchanged.

A successor Naming lane may observe an original `brainstorm_v1` execution using its actual current slot and the frozen original execution handle. The job, original deployment, admission, request and execution token remain unchanged. This new cross-deployment path admits only `recover`, `brainstorm_state`, and a completed `brainstorm_event`; it cannot create, claim, publish, finish, cancel or submit tools. Other historical profiles keep their previous same-deployment behavior. The companion frozen observation-containment patch must also be applied; it retains typed nonsecret diagnostic codes and contains retrieval/validation failures without hiding SQL persistence failures.

Observation never publishes saved names. Any fixed-job operator resolution is a separate reviewed operation that derives candidates from the retained completed response, validates the unchanged current brief/history, and preserves unknown financial accounting. It must refuse incomplete evidence or fewer than 100 eligible names. No automatic inference retry, fabricated lease or silent admission rebinding is permitted. A normal worker process is not a one-shot observation mode and may accept other normally admitted work.

The native qualification is synthetic PostgreSQL17.11/Linux evidence, including high-entropy 113/120-candidate payloads, full equality/collision checks, concurrent writers, exact terminal replay and conflicts, rollback, source/security preservation and restricted-role cross-deployment observation. It is not a successful live recovery or a new paid benchmark. A final production bundle must be built from the actual clean merged revision; review builds must retain `sourceClean:false`.
