# Names guided workshop

On 2026-10-10 the user selected [Fluid — Screens, Names](https://www.figma.com/design/HP219GuYbpE8F1wHxj0h6N/Fluid-%E2%80%94-Screens?node-id=3-7). The page contains four approved desktop layouts: Affix `7:2960` (1440 × 1509), Tweaks `28:3032` (1440 × 1651), Blend `28:6715` (1440 × 1437), and Swap `28:7323` (1440 × 1323).

The implementation uses the original 80 px rail, 76 px toolbar, Geist, neutral/magenta tokens, centered 1008 px workbench, word chips, four transformation tabs, affix columns, ten tweak cards, order panel, and favorite result pills. Original SVGs are exported unchanged into `public/names/`, including each mode's grid and the Names shell. Figma reference markup is inspected for geometry and never imported as application code. The sample words appear only in isolated browser tests; production starts empty.

The workshop performs deterministic transformations locally. Prefixes and suffixes are independent variants. Selected tweaks run in their fixed displayed order, preserving capitalization except the explicit case operation. Blend tries both word directions, removes spaces and punctuation, joins overlapping letters, and deduplicates names. Swap uses bounded spelling heuristics at Safe, Balanced, and Creative levels, without linguistic or availability guarantees. Blend and Swap use original words independently of the retained affix/tweak settings.

Implementation bounds are 300 unique source words, 300 preview results, twelve custom prefixes/suffixes, twenty saved word lists, and at most 6000 blend attempts. Saved lists include captured context and can restore words; they stay in this browser. Existing linked seed words retain their source identity and context. For a blend, the first word supplies captured context and ancestry; the exact normalized second word and cuts are recorded in the blend input. Contexts are never silently merged.

Live previews do not create retained candidates or transformation runs. An explicit favorite atomically records its complete replayable chain through the existing pinned transformation contracts. The extra tweak operations and spelling replacements are recorded as exact literal substitutions; the shared version-1 algorithms, history reader, account schemas and database remain unchanged. Favorite and saved-name flags remain independent. Empty, unchanged and oversized transformations are omitted honestly. Re-favoriting the same source, context and recipe reuses its retained candidate. Capacity failures add no partial chain and prune no existing work.

Library, Saved word lists, and History are separate views. Existing manual capture, comparisons, brand promotion, backup downloads and storage recovery remain available. Single-name controls retain the original explicit workshop operations; AI Assistant retains the owner-fenced account/project bridge. Browser-store version 1 accepts an optional guided UI section, keeping existing workspaces readable. Account data is never written to browser storage automatically. No provider, paid call, migration, credential or availability integration is activated by this implementation.

Verification covers all four desktop layouts, mobile behavior, native SVG geometry, word entry and mode changes, keyboard tabs, independent affixes, ordered tweaks, original-word modes, result limits, real clipboard calls, list restoration, favorite history replay, old workspace compatibility, account fencing, promotion and storage failure/conflict recovery. Browser API responses are isolated fixtures; these checks do not claim live provider or database acceptance.
