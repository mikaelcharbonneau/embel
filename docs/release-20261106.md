# Competitor research fix release — November 6, 2026

This release publishes source `79eb8f2863f0610915c3fc441842097205122722`
("Keep verified competitors when one research source cannot be verified",
[PR #190](https://github.com/mikaelcharbonneau/embel/pull/190)) to the existing
shared worker. It changes no database schema, SQL function, provider policy or
web code path. The web deployment was not republished: the live web source
`b0444144` differs from the release source only in the worker's Strategy
response handling and its tests.

- Local: 65 strategy, research and guided test files (1,050 tests) pass on the
  release source, as do the shared-lane worker suites (57 tests) and the
  research worker/database suites; type check and lint are clean. The two
  `shared-pool-configuration`/`shared-pool-preflight` files fail on macOS for
  host-environment reasons (see PR #188) and pass on CI.
- Before release, a local run with the same worker code retried the failing
  brief: the model offered three competitors, one with an unobserved website was
  dropped and two verified competitors were shown with clean descriptions
  (recorded charge $0.053).
- After release: `/api/health` reports release `b044414` (web unchanged), the
  unauthenticated session route returned 401, there are no unfinished
  executions, and the 9 historical `needs_reconciliation` jobs are untouched.
- No paid AI generation or signed-in browser journey was run in production
  after the release. Lease renewal and Naming readiness establish worker
  qualification, not output quality.
