# Shared three-lane worker

This is the replacement worker architecture for the shared runtime. `npm run build:shared-worker` (also the primary `build:account-worker` alias) builds one bounded process with actual Strategy, Naming and Logo engines. The old per-customer account-enrollment/Vault launcher and its unapplied provisioning packet are legacy sources, not this runtime's activation path.

Startup is disabled unless `EMBEL_SHARED_WORKER_POOL_ENABLED=true`. Enabled startup requires explicit `EMBEL_SHARED_WORKER_POOL_CONFIGURATION` and `EMBEL_SHARED_WORKER_POOL_SECRETS` project-sensitive settings. No agent key, default database login, customer password, dynamic secret store, Auth administrator credential or hosting target is inferred. A fixed Logo slot uses its own preapproved service Auth actor; no actor is created per customer or by this process.

Configuration includes the isolated target, actual source/artifact/runtime fingerprint, complete approved slot identities, static policy/model verification bindings, reviewed RPC proofs, queue routing and capacity. Development permits only distinct canonical `127.0.0.1` service ports with the explicit development gate, development/test mode and no Vercel markers. Hosted staging requires matching real Vercel project/deployment metadata on an isolated protected project. Production origins/project references and preview deployments are refused here. The entrypoint independently hashes the built artifact; dirty local source can be inspected but cannot qualify hosted staging.

The database proves the exact complete enabled slot set across replicas. Global active execution capacity equals that fixed set; `maxPerTenantPerLane` is checked against the database's uniform owner-plus-lane bound. One owner can use independent lanes concurrently. Each fixed slot has a two-connection pool. The controller has no per-customer process, connection map or credential. Bounded native raster helpers remain part of the Logo engine.

Before any proof RPC, qualification checks actual role/OID/TLS and compares the source-owned native authority manifest against one catalog query under a read-only transaction and empty search path. This includes the bounded new/changed worker graph, private backups and wrapped legacy seams. It needs no private schema access. Body, owner, language, volatility, definer/search-path settings and broad EXEC exposure must match. Intentional legacy owner/RLS exposure is retained explicitly. This detects release/permission drift; it is not a claim of protection from a malicious database administrator.

Strategy's durable outbox publishes with the native Queue SDK in the same worker project, topic, fixed `iad1` region and deployment as outbound polling. No inbound Daemon listener or cross-project HTTP publisher exists. Only an actual broker message ID can mark publication. A retry or uncertain journal result throws/reschedules; a qualified engine's durable terminal ACK, including recorded reconciliation state, is honored. Queue/project permissions and hosted routing still require real staging validation.

Slot leases carry instance, generation and token fences. Old issued observations retain their immutable execution scope; they never become new paid creates. Recovery reads at most 25 records per page and invokes only the actual lane's observation path. Known provider handles or issued immutable outputs may be read back; absent handles remain explicitly unresolved. Other eligible projects can progress. A fatal journal/drain error withdraws the slot instead of renewing false health.

On shutdown, the controller fences admission immediately, stops new receives and awaits actual SDK/engine work. A bounded drain failure logs an unconfirmed event and terminates the local process with a failure status; it never claims the remote provider stopped or clears unknown accounting evidence.

The build checks SQL packet hashes and a reviewed first-party source allowlist, bundles the native authority manifest, and records source/artifact hashes. `node .tmp/shared-worker/index.js --describe` reports only artifact/runtime metadata. Running without the enable flag exits disabled. Build/probe success is not hosted installation, provider readiness or paid acceptance. This source task creates no persistent roles, credentials, accounts, services or deployment.
