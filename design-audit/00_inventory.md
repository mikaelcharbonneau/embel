### Observations from the click-through (not fixes; for the later passes)

Use Enter or direct URLs in the pane.

The Assets step is its own page (`…/logo/deliverables`) and shows "Preparing…" placeholders until the browser has built the files, then "Ready to download."

## 3. Flows

Entry points and exits, all from code and confirmed in the browser. Every AI step costs credits (30 / 150 / 500 a month); all were run against the stand-in AI.

1. **Start a brand.** Home → type a brief (or tap a starter chip) → Send prompt. Signed out: the Sign in overlay opens and the unsent prompt is kept. Signed in: a project is created and the browser goes to `/brands/account/<id>?view=strategy`; competitor research starts by itself. Exit: the project conversation.
2. **Strategy** (same page). Competitors (research with sources; keep some) → Audience → Positioning. States: researching with Cancel research, research failed with Retry research, results. Exit: "Strategy · Complete" card with Edit strategy.
3. **Voice** (same page). Personality (one of three) → Name (up to 100 generated names, previews open in a dialog, or type your own; Change name) → Slogan (optional, "Skip for now").
4. **Identity** (same page). Inspiration (like whole brands or parts in a gallery of 56, or add own images) → Logo (choose logo types, "Explore six concepts", choose one, refine by describing a change, "More concepts", Download PNG) → Creative direction (three boards, choose one, "More directions"). Exit: Continue → Assets.
5. **Assets** (`…/logo/deliverables`). Brand images (brand board, five social images and templates) → Brand guidelines (Overview, Logo, Colors, Typography, Voice, Imagery) → Design system (tokens as CSS or JSON). Downloads built in the browser: brand kit ZIP, brand board PNG, guidelines HTML, tokens.
6. **Account.** Sign up → confirmation email → `/auth/callback` → `/sign-in?confirmation=complete`; Sign in (page or overlay); Forgot password → email → `/reset-password`; Sign out (confirmation dialog when there are unsaved edits).
7. **Projects.** `/brands`: search, sort, project options → Delete (dialog) → Deleted projects → Restore. Each card links to the stage-specific URL (`/logo`, `/inspiration`, `/logo/directions`, `/logo/deliverables`, `?view=strategy#strategy-personality`).

## 6. How to run `capture.mjs` (and the sibling scripts)

Everything is local-only: each script refuses any address that is not `127.0.0.1`/`localhost`.

```bash
# once per boot
colima start embel && npm run dev:up
node design-audit/seed/seed.mjs         # fresh, known data (about 3 min); refuses to run while the app is up
node design-audit/seed/serve.mjs        # app on :3105 + stand-in AI on :3186 (leave running)

node design-audit/capture.mjs                         # every route, state and width -> design-audit/evidence/screens/
node design-audit/capture.mjs /some/other/folder      # same file names elsewhere (for before/after comparisons)
node design-audit/capture.mjs --only=kestrel,hover --widths=1440
node design-audit/capture.mjs --failed                # re-run only what the last run reported as problems
node design-audit/capture.mjs --list                  # print every state (and skipped ones with the reason)
node design-audit/capture.mjs --recipes               # ALSO the states that change data; reseed afterwards
node design-audit/capture-exports.mjs                 # download the Kestrel kit and render every file
node design-audit/capture-emails.mjs                  # render the two email templates
node design-audit/scan-assets.mjs                     # asset inventory -> evidence/assets/
```

How it behaves: it signs in by itself with `design-audit/.audit-credentials` (form sign-in, session saved to `design-audit/.auth/<account>.json`, re-checked on every run, re-created if it has expired), using `audit-fresh` for empty states, `audit-free` for 0 credits and every journey stage, and `audit-pro` for the paid account and the finished brands. Brand ids are read from `.logs/last-seed.json` (they change on every reseed). If a page that must be signed in shows the sign-in prompt, the whole run stops with exit code 2 and says which account and route. Other failures are listed at the end (exit code 1) and the failed state leaves a `FAILED__<file>.png`; fix, then `--failed`. Screenshots are full length, taken after fonts and images have loaded, with animations and transitions switched off and `prefers-reduced-motion` on, the Next.js dev badge hidden, a fixed locale and time zone, mouse parked off the page; two runs on the same seed should match except for data that changes by itself ("Today" dates, usage rows). Elements are found by role, label, visible text or URL, never by class name. A full run is about 12 minutes with 3 workers.

Manual steps and caveats:

1. The app, the stand-in AI and the seed must be running (above). Always reseed after `--recipes`.
2. `--recipes` states (research in progress / failed, logos being drawn / failed) set the stand-in AI mode over HTTP and put new briefs into audit-pro; the two logo recipes capture 1440 only (one active logo run per brand). The script puts the stand-in back to normal at the end.
3. Locators follow today's labels (for example "Pick up where you left off", "Project options for …", "Explore six concepts"). After a redesign that renames them, run `--list`, then `--failed`, and update the matching `state(...)` block; the state and file names do not need to change.
4. In the Browser pane, use Enter and direct URLs for sign-in and wait ~1.5 s after load before clicking the pill (see section 1 observations).
5. `evidence/` is about 80 MB (screens 65 MB). It is inside `design-audit/` and was not added to git or `.gitignore`.
